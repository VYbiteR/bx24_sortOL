# API подключаемых модулей

Подключаемые модули позволяют дополнять ANIT B24 Chat Sorter, не изменяя код ядра расширения. Совместимыми считаются только интерфейсы, описанные в этом документе.

## Структура модуля

```text
modules/
├── registry.json
└── example-module/
    ├── content.js
    └── page.js
```

- `content.js` выполняется в изолированном контексте расширения. Здесь доступны API Chrome, включая `chrome.runtime`.
- `page.js` выполняется в контексте страницы. Здесь доступны `window.BX`, DOM страницы и API ядра расширения.

Оба файла обязательны, даже если один из них пустой.

Модуль может загружаться в нескольких фреймах. Код инициализации должен быть идемпотентным:

```js
(function () {
  if (window.__EXAMPLE_MODULE_LOADED__) return;
  window.__EXAMPLE_MODULE_LOADED__ = true;

  // Инициализация модуля.
})();
```

## Регистрация модуля

Модули подключаются через `modules/registry.json`:

```json
[
  {
    "name": "example-module",
    "endpoint": "https://example.com/api/module.php"
  }
]
```

Поля:

| Поле | Обязательное | Описание |
|---|---|---|
| `name` | Да | Имя папки модуля. Допустимы латинские буквы, цифры, `_` и `-`. |
| `endpoint` | Для серверных запросов | HTTPS-адрес, на который ядро отправляет запросы модуля. Query-параметры и fragment не поддерживаются. |

После добавления или изменения модуля перезагрузите расширение и вкладку Bitrix24.

## API меню сообщений

API доступен в `page.js` через глобальный объект:

```js
const api = window.__ANIT_BXCS_TASK_MENU__;
```

Перед использованием проверяйте его наличие:

```js
const api = window.__ANIT_BXCS_TASK_MENU__;
if (!api) return;
```

### `registerMessageAction(action)`

Добавляет действие в контекстное меню сообщения:

```js
api.registerMessageAction({
  id: 'example-action',
  label: 'Пример действия',

  async run({ chatId, messageId, target }) {
    // Действие модуля.
  }
});
```

Поля действия:

| Поле | Тип | Описание |
|---|---|---|
| `id` | `string` | Уникальный идентификатор. Допустимы латинские буквы, цифры, `_` и `-`. |
| `label` | `string` | Название пункта меню. |
| `run` | `function` | Функция, вызываемая при выборе пункта меню. Может быть асинхронной. |

Аргумент `run`:

| Поле | Тип | Описание |
|---|---|---|
| `chatId` | `number \| null` | Числовой ID чата, если его удалось определить. |
| `messageId` | `number \| null` | ID выбранного сообщения, если его удалось определить. |
| `target` | `Element \| null` | Найденный DOM-элемент сообщения. |

`chatId` и `messageId` могут быть `null`: интерфейс Bitrix24 не всегда содержит эти значения в DOM. Модуль должен проверить необходимые значения самостоятельно.

Если `run` выбросит необработанную ошибку, ядро запишет её в консоль и покажет пользователю уведомление Bitrix24.

### `openTaskFromMessage(chatId, messageId)`

Открывает штатную форму создания задачи Bitrix24 из выбранного сообщения:

```js
await api.openTaskFromMessage(chatId, messageId);
```

Метод использует `BX.Messenger.v2.Lib.EntityCreator`. Модулю не нужно искать штатный пункт меню или имитировать клики.

Метод выбрасывает ошибку, если сообщение не определено или форма создания задачи недоступна.

### `showError(message)`

Показывает нативное уведомление Bitrix24:

```js
api.showError('Не удалось выполнить действие');
```

Если модуль выбрасывает ошибку из обработчика `run`, отдельно вызывать `showError` обычно не требуется.

## Серверные запросы

`page.js` не имеет доступа к API Chrome. Для обращения к серверу модуль передаёт данные из `page.js` в свой `content.js`, а `content.js` вызывает фоновый процесс расширения.

Низкоуровневый запрос из `content.js`:

```js
const response = await chrome.runtime.sendMessage({
  type: 'ANIT_BXCS_MODULE_POST',
  module: 'example-module',
  code: '123456',
  body: {
    chat_id: 15024
  }
});
```

Поля сообщения:

| Поле | Тип | Описание |
|---|---|---|
| `type` | `string` | Всегда `ANIT_BXCS_MODULE_POST`. |
| `module` | `string` | Имя модуля из `registry.json`. |
| `code` | `string` | Значение заголовка `X-ANIT-Time-Code`. |
| `body` | JSON | Тело серверного запроса. |

Успешный ответ фонового процесса:

```json
{
  "status": 200,
  "data": {
    "group_id": 406
  }
}
```

Ошибка фонового процесса:

```json
{
  "error": "Описание ошибки"
}
```

Ядро выполняет запрос со следующими параметрами:

- метод `POST`;
- адрес берётся только из `modules/registry.json`;
- таймаут — 5 секунд;
- `Content-Type: application/json`;
- `X-ANIT-Time-Code` содержит значение поля `code`;
- cookies и другие авторизационные данные браузера не отправляются;
- тело формируется через `JSON.stringify(body)`.

Для передачи данных между `page.js` и `content.js` модуль может использовать `window.postMessage`. Типы сообщений и формат данных внутри модуля определяет сам модуль.

## Безопасность

- Не храните в модуле постоянные пароли, приватные API-ключи и другие секреты: пользователь может прочитать исходный код установленного расширения.
- Проверяйте входящие сообщения в `content.js`: источник должен быть текущим окном, а тип сообщения должен принадлежать модулю.
- Сервер не должен доверять `chatId`, `messageId` и другим данным только потому, что запрос пришёл от расширения.
- Не вставляйте полученные строки через `innerHTML`. Для обычного текста используйте `textContent`.
- Не передавайте серверу содержимое чатов без явной необходимости и согласия пользователя.

## Совместимость

Публичный интерфейс текущей версии состоит из:

- формата `modules/registry.json`;
- файлов `content.js` и `page.js`;
- `window.__ANIT_BXCS_TASK_MENU__.registerMessageAction()`;
- `window.__ANIT_BXCS_TASK_MENU__.openTaskFromMessage()`;
- `window.__ANIT_BXCS_TASK_MENU__.showError()`;
- сообщения фонового процесса `ANIT_BXCS_MODULE_POST`.

Внутренние объекты `window.BX`, DOM-классы Bitrix24, функции ядра и сообщения, не перечисленные выше, не являются публичным интерфейсом и могут изменяться.

Несовместимое изменение или удаление документированного интерфейса должно сопровождаться увеличением основной версии расширения.

Параметр `apiVersion` пока не поддерживается. При его появлении он будет отдельно описан в этом документе.
